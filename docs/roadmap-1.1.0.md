## 2. 已完成部分（可直接依赖）

### M0 通道实测（2026-09-25 实测数据）
- 内核：**ungoogled-chromium 109.0.5414.120**（GitHub 直连可取，官方 SHA-256 已写进脚本）。
  Google 快照桶只有 `109.0.5414.0`（分支早期）；npmmirror 没有镜像。
- 单连接下载只有 ~2 KB/s，**必须 `--parallel 6`**（实测 ~300 KB/s）。
- 化学数据源：Wikidata（CC0，会 429 限流）、PubChem、NIST WebBook（热化学）、ChEBI 本体（258 MB，CC BY 4.0）。
  ATcT 403 不可用；JANAF 的表格页编号推不出来，改用 WebBook 按 CAS 取。

### M1 内核与 exe
- 启动器**优先用随包内核**，找不到才退回老师的浏览器；内核有独立 profile（老师机器上的 360/Chrome profile 比 109 新，不能共用）。
- **不要解到用户目录下**：实测 `C:\Users\<用户>\` 下内核的 GPU 进程会 `STATUS_DLL_INIT_FAILED` 连崩三次然后 FATAL；
  `--disable-gpu`/`--in-process-gpu`/`--disable-gpu-sandbox` 都救不回来，只有 `--no-sandbox` 或换位置。
  解包位置顺序：**程序目录 → %ProgramData% → 用户目录**；内核起不来时按 **关 GPU → 关沙箱** 两级自动重试（每次记日志）。
- 升级会**自动清掉旧版本解包目录**（一份 300 多 MB）。
- 首次运行**自动建桌面快捷方式**（`config\installed.txt` 当标记，老师删了不会反复种回来）。
- 单文件 exe 尾部格式：`[exe][payload tar.gz][戳][payload 长度 8][魔数 8][戳长度 4]`（`launcher\Payload.cs` 读法）。
  打包必须 `scripts\make-exe.py`；改外壳时用 `--payload build\payload-<版本>.tar.gz` 复用（秒级）。

### M2 发布流程
- `scripts\make-release.py` 产出**两样**：`dist\study7agent-<版本>.zip`（对外分发：exe + 使用说明.txt）
  与 `dist\study7agent-<版本>-deepseek.zip`（同一份 exe + 预填 `config\agent.json`）。
  两个 exe **字节完全相同**，密钥永远不进二进制。打完自己扫两遍（exe 按字节、zip 逐成员）。
- 客机验收：`powershell -File scripts\vm-acceptance.ps1 -Exe`（约几分钟）；
  **VM 现在是关机状态**（老师关的），要跑验收之前先让它开机。

引擎能力（`webui\chem.py`）：
- `parse_formula` / `canonical_formula`（HNaO → NaOH）/ `simplify_chinese`（碳酸鈣 → 碳酸钙）

- `lab_mix` / `lab_heat` / `lab_catalog` / `lab_presets`（实验台）
- **`visual` 契约**（界面只画、不懂化学）：`{gas, precipitate{formula,color}, solids[], solution_before, solution_after}`
- 红线：规则表里查不到的一律 `资料未收录`，**绝不编造**；推出来的反应带 `predicted` 标记。

## 3.5 M4.5 实验台仿真化（**进行中**）

老师 2026-09-25 提的六件事，逐条对应：

| 老师说的 | 怎么做的 |
| --- | --- |
| 药品太少（只有 14 瓶） | 试剂架 14 → **165 瓶**：手写的那批（标签/颜色最讲究的：大理石、稀盐酸、浓硫酸、银氨溶液…）+ **按"阳离子 × 阴离子"生成**的一整套（Na/K/NH4/Ca/Ba/Mg/Al/Zn/Fe2/Fe3/Cu/Ag × Cl/NO3/SO4/CO3/HCO3/SO3/OH/S/SiO3/CH3COO）。生成规则在 `rules.reagent_grid` 里：中文名 = 阴离子名 + 阳离子名，固体还是溶液按溶解性判，`skip` 里是**不该摆上架子**的组合（Al2(CO3)3 双水解、Fe2S3 遇水分解、NH4OH 不存在…）。顺带把 `split_salt` 升级成"查表 + 电荷守恒反推"，所以像 FeS、CuSO3、Na2SiO3 这些没手写的盐也能参与反应（FeS+2HCl=FeCl2+H2S） |
| 试剂架要有常见有机物 | 有机物 **37 瓶**：烷烃（甲烷/乙烷/丙烷/丁烷）、烯炔（乙烯/丙烯/乙炔）、醇（甲醇/乙醇/乙二醇/甘油/苯甲醇）、醛（甲醛/乙醛）、酸（甲酸/乙酸/草酸/苯甲酸/硬脂酸）、酯（乙酸乙酯）、卤代烃（溴乙烷/四氯化碳）、芳香（苯/甲苯/二甲苯/苯乙烯/苯酚/硝基苯）、糖（葡萄糖/果糖/蔗糖/麦芽糖/淀粉/纤维素）、氨基酸/尿素/油脂/蛋白质 + 溴水/碘水/氧气/氯气/二氧化硫/硫化氢 + 银氨溶液/新制氢氧化铜/浓硫酸/浓硝酸。<br>反应表 **37 条有机 + 8 条特例**：燃烧、催化氧化、酯化（可逆、要浓硫酸）、酯水解（可逆）、糖类水解、皂化、加成（溴水褪色）、苯的溴代/硝化/加氢、甲苯氧化、溴乙烷水解与消去、乙醇与钠、银镜与斐林、蛋白质变性；特例那 8 条是离子模型算不出来的（铝/锌与强碱、二氧化硅与碱、氯气与碱、Fe3+ 氧化 Fe/Cu、Cu 置换银、亚硫酸盐/硫化物遇酸出气） |
| 拖动药品看不出在拖什么 | 跟着鼠标的是一个**画出来的药瓶**（瓶身 + 液面颜色 + 名字），仪器也是**画出来的器皿轮廓**，抓着台面上的仪器挪位置时原件变虚（`.dragging`）。坑：面板是 `showModal()` 打开的 `<dialog>`，它在**顶层（top layer）**里——ghost 挂到 `document.body` 上会被对话框和 `::backdrop` 盖住，**看得见才怪**；必须挂进 `dialog[open]` 里（`labGhostHost()`）。自检也因此改成"拖动中途截图 + 断言 ghost 在 dialog 里、跟着光标、宽高非零"，只断言"元素存在"是抓不到这个 bug 的 |
| 刚拖入没有任何现象，点加热才莫名出现 | 反应**加进去就算**：`op=sim` 一次给"反应 + 限度 + 速率 + 从 0 秒开始的时间轨迹"，界面照着播；条件不够的（要加热/要浓硫酸/要催化剂）**明确写缺什么**，不再是"什么都没发生" |
| 点一次加热多一层黑固体（KMnO4+HCl） | 组成**每帧都由引擎给**（`appearance` 说每种物质画成液体/固体/沉淀/气体），界面不再自己往数组里 push；自检里钉了"同一份东西算两次组成必须一样" |

  * 示例的**时长没传给服务端**（`scene()` 里写死 8 秒），所以装载

    （环己烯 = 半椅式，四个碳近共面、两个翘出去）；

### M13.4 作图面板：隐式方程 + 动点/切线 + 老设备点不出来（**完成**）

- **根因（真 bug，不是"没实现"）**：`plane.js` 是**唯一一个只用 Pointer Events** 的前端文件
  （别的面板都是 `mousedown`）。Win7 上双核浏览器（360/搜狗）的旧 Blink 内核早于 Pointer Events
  （Chromium 55），`addEventListener('pointerdown', …)` **注册得上、永不触发**——不报错、不提示，
  于是点不出动点、拖不动，连平移缩放一起失效。同段代码还有两个静默失效点：
  `ResizeObserver` 回调里直接调 `requestAnimationFrame`（缺了它尺寸落定后永不重排），
  以及 `{passive:false}` 选项对象在旧内核上可能抛 TypeError —— **抛在 `boot()` 里会让后面所有
  监听器都注册不上**。
- **修法**：`inputCapability()` 探 `typeof window.PointerEvent === 'function'`，缺了就换
  `mousedown/mousemove/mouseup/mouseleave`；`listen()` 选项对象失败退回布尔形式；
  `frame()` 缺 rAF 走 `setTimeout`；诊断与 `W7Plane.input()` 能看出走的是哪一路（"绝不静默失效"）。
- **隐式方程**（`x^2+y^4=16` 这类）：`plane_math.py` 新增 `curve_glider/curve_projection/
  tangent_direction/_pull_to_curve/_nearest_on_segments/_segments_at`，`point_on_object` 接上
  方程/参数/极坐标三类曲线；动点=**投影到最近采样线段**后按弧长占比取参，切线改用**方向向量**
  （不再用斜率，竖直切线不会 NaN）。`plane.py` 里显函数仍走符号求导（老行为不变）。
- 实测：隐式动点 `|F(x,y)|` 最差 1.8e-15；切线方向与数值梯度夹角 < 1e-3 度；`dy/dx=-F_x/F_y` 对拍；
  x²+y²=4 在 (2,0) 的竖直切线无 NaN；就近点与暴力枚举一致；拖动一次服务端重算 0.77 ms。
- 防回归：新增 `TestImplicitGliderAndPointDrag`（13 项），前端纯函数抽到 node 里真跑
  （含 `x*y=1` 双支不跨支、没有 PointerEvent 时的事件名回退与 rAF 兜底）。
- **踩的坑**：随包启动器是按 **.NET 2.0** 编的（Win7 上一定有），`Path.Combine` 只有 2 参数重载 ——
  写 5 参数版本立刻 `error CS1501`（本地用 v4.0 编译器试是发现不了的）。
- 没验：**真机 / 老内核没实测**（"没有 PointerEvent"是 node 里 `delete window.PointerEvent` 模拟的，

## M17 AI 画的几何图形边长粗到糊成一坨（2026-10-06，**完成**）

老师原话（m01474）：**"让AI画一个几何图形会叠一堆图像，表现为边长特别特别粗"**。

**根因：多边形的描边不是按屏幕像素画的，是按"数据单位"画的。**
平面上那层 SVG 的 `viewBox` 直接就是数据坐标（`applyView()`，`webui\ui\plane.js` 里
`setAttribute('viewBox', view.xmin + ' ' + (-view.ymax) + ' ' + width + ' ' + height)`），
所以 **1 个"用户单位" = 画布像素 ÷ 数据跨度**：默认视野宽 20 单位、画布约 700px 时，
1 单位 ≈ 35 像素。而 `webui\ui\plane.css` 里 `.plane-poly` 写的是 `stroke-width: 2.2`
—— 不带 `vector-effect: non-scaling-stroke` 时，那 2.2 就是 **2.2 个数据单位 ≈ 70 多像素**：
三角形的三条边各自 70 多像素宽、在图形中间叠起来，看上去就是"边长特别特别粗、糊成一坨、
像叠了一堆图"（`docs\ui-plane-thick-probe.png` 变体 1 就是当时的效果，变体 2 加上属性、变体 3
用线段画同一个三角形，都是正常的 2.2px）。

**只有那两处漏了**：plane.js 里所有描边图元都在元素上带了 `'vector-effect': 'non-scaling-stroke'`
（网格线/坐标轴/线段/直线/射线/向量杆/圆/函数曲线/轨迹/滑杆，连用**同一个** `.plane-poly` 类的
扇形 `path` 都带了），只有 `drawPolygon()`（多边形）和 `drawRegion()`（不等式区域）没带。
`plane.css` 里 `.plane-label` 的白圈描边也是**显式折算**的（`element.style.strokeWidth = U(3) + 'px'`
带中文注释），刻度字号走 `setFont()` 折算 —— 可见这是漏写，不是有意。

**改了什么**（`webui\ui\plane.js`）：`drawPolygon()` 与 `drawRegion()` 里那两个 `svgNode('polygon', {...})`
各加 `'vector-effect': 'non-scaling-stroke',`，并留中文注释说明"viewBox 用的是数据坐标，
漏掉这条 2.2 就成了 2.2 个数据单位"。`drawRegion` 今天 `.plane-region` 是 `stroke: none`（没有视觉问题），
一并补上免得以后一加描边又糊。
