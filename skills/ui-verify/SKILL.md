# 在别的窗口里动手的纪律

老师原话："感觉 ai 在别的窗口操作的时候比较蠢。" 蠢通常不是不会点，而是
**点了不验证、错了还接着点**。按下面这几条来。

**先说清这一版的代价**：新工具面是"真鼠标"路线——`click` / `type` / `scroll` / `move` /
`multi_*` / `draw_path` 都会**真的移动老师屏幕上的鼠标、真的按键**，没有"悄悄点一下不打扰老师"的后门。
所以动手前先问自己：这件事非得动鼠标吗？

## 动手前
- 先 `snapshot` 看**现在**什么样：窗口是不是在前面、有没有弹窗挡着、停在哪儿。
  别拿几轮前的印象开干。窗口清单也在 `snapshot` 的文字里（省略 `window` 就是整个桌面）。
- 能不动鼠标就别动：能用 `run_command`（命令行）、`read_file`/`write_file`、
  `clipboard`、`app(mode="switch")` 切窗口、`send_qq_message` 这类现成通道办成的，
  就不要走"点像素"。
- 要动鼠标就**先跟老师说一句**"我要动你的鼠标点 XX"，老师正在用电脑时更要先说。

## 动手时
- **一次只做一件事**，做之前用一句话说清"我要点哪儿、为什么"。
- **优先用 `label`，别报像素坐标**：`snapshot` 的元素清单里每个元素都有 `[编号]`，
  截图上的红字就是它。`click(label=12)` 会按**当前界面**重算这个控件的坐标
  （界面变了会退回去并告诉你），比 `click(loc=[x,y])` 稳得多。
- 非要用 `loc` 时：坐标是**屏幕物理像素**，来自刚截的那张图；窗口被移动过就得重新 `snapshot`，
  否则会被"画面已经变了"挡下来（这是保护，不是故障）。
- 带副作用的按钮（确定 / 下一步 / 删除 / 关闭 / 覆盖）格外确认位置对不对、
  编号是不是那个按钮。
- 输入：`type(text=..., label=N)` 会先点一下那个输入框再打字；中文直接给 `type`（它走 Unicode 注入），
  快捷键走 `shortcut("ctrl+s")`，方向键/回车等单键也是 `shortcut("enter")`。
- 要往下看/翻页：`scroll(label=N, direction="down", wheel_times=3)`（在内容区滚），
  **不要拖滚动条**——滚动条又细又容易拖飞。
- 弹窗来了先读标题和按钮（取消 / 确定 / 是 / 否 / 不再提示），别闭眼点确定；
  系统弹窗（UAC、杀软）不替老师决定，叫老师来处理。
- 关不掉的面板按 Esc（`shortcut("esc")`）；关不掉的窗口才用 `app(mode="close", name=...)`。

## 动手后（最容易省掉的一步）
- **重新 `snapshot` 一次看结果**：点下去 ≠ 事情办成了。以新状态为准，不以"我点了"为准。
- 等界面反应过来用 `wait_for(condition="window"|"text"|"gone"|"stable", text=...)`，
  别用 `wait` 干等一大段；连续 `wait` 多半说明该换个判断条件。
- 没成功：看新状态想清楚为什么（点偏了？窗口换了？还得先登录/选文件？），再决定下一步。
  **同一个动作最多重试两次**，第三次必须换方法或问老师。
- 失败就如实说失败（带上屏幕上的原话），不要用"应该已经好了"糊过去。
- 每一步都告诉老师"现在在做什么、下一步做什么"，别闷头点十几下。
- 老师正在用这台电脑：慢一点、稳一点，别连续快速点击（鼠标被抢走对老师是很烦的事）。
