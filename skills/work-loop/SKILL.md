# 多步任务：拆小、每步验证、留断点

## 1. 动手前：一句话说清打算怎么做
- 用 1–3 行列出步骤（例如"1 读原件 → 2 写新稿 → 3 转 pptx → 4 核对页数"），
  然后**立刻开始第一步**。不要把计划写成一篇小作文，也不要只给计划不动手。
- 每步都写清**验收标准**：这一步做完，怎么算成了（文件存在？页数对？窗口标题对？）。

## 2. 每一步：一个动作 + 立刻验证
- 做完一步马上验证（读回文件、看窗口、查对象、核对页数），确认后再进下一步。
- 顺序：先做**能验证的**，再做靠猜的；先把原件读清楚，再动手改。
- 出错就停在那一步，把错误原话带上，说清"卡在哪、下一步打算怎么绕"，
  不要一路往下做，最后交一堆带着错误的结果。

## 3. 长活留断点（这个项目的历史会自动压缩）
历史被压缩之后你只能看到摘要，所以**每完成一个阶段，就在回答里留一小段断点笔记**：

```
断点：已做完 A、B；下一步 C（要用的路径：…）；坑：X 不能用，要改用 Y。
```

超过五六个步骤、或者要跑很久的活，就把这段笔记写进工作区的一个 md 文件
（例如 `进度-<任务名>.md`），需要时读回来。这比"压缩后从零猜"省得多。
需要独立子任务时用 `run_subagent`（一个子代理一件事，别把整活都丢给一个子代理）。

## 4. 别做没要求的事
- 不顺手改别的文件、不顺手重排格式、不顺手"优化"老师没提的东西。
- 老师只说"看一下"就别动手改；说"改这份"就只改这一份，原件另存。

## 5. 收尾三件套
1. **做了什么**（一两句，人话）；
2. **东西在哪**：交付文件的完整路径（老师要能直接点开）；
3. **哪些没验 / 有什么遗留**（例如"页数没逐页核对""这份需要联网才能刷新"）。
   没验的部分必须写出来，不要用"已完成"一笔带过。
