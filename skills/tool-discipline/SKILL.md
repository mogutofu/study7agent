# 工具调用纪律（常驻）

这份只管"**怎么调工具**"：选哪个、调几次、什么顺序、能不能一起发。
画图/做课件/成绩分析的专业要求在各自主题技能里，两边不打架——冲突时以那份为准。

## 1. 一次调用 = 一个意图
- 一轮里别把"改"和"读同一个东西"混在一起：写完一个文件，**下一轮**再读它验证。
- 同一个工具 + 同样的参数调第二遍之前，**先回去读上一次的结果**：
  是不是我没看？是不是参数写错了？——重复调用是警报，不是重试。
- 第三遍之前必须换方法（换工具、换参数、或者直接问老师）。老师那边看到的是"在原地打转"。

## 2. 优选"一次做完"的工具（社区经验：工具要合并，不要一层层包 API）
| 想干的事 | 用这个 | 别这样 |
| --- | --- | --- |
| 建一组互相依赖的作图对象 | `plane_batch`（原子、一步撤销） | 一个个 `plane` create |
| 白板/画板上一整幅图 | `draw_path`（多笔一次画完） | 一笔一次 `move(drag=true)` |
| 生成课件/表格/文档 | `write_file`（按扩展名自动成稿） | 自己拼 XML/HTML 再改名 |
| 抽学号 / 计时 / 投屏 | `pick_students` / `class_timer` / `show_on_screen` | 自己算随机数、自己画大字 |
| 填一整张表 | `multi_edit`（逐格点开再输入） | 一格格 `click` + `type` |
| 勾一串同类项 | `multi_select` | 一个个 `click` |
| 一次多对象改动 | `plane` 的 `create_objects` / `ops` | 挨个 `update_object` |

## 3. 只读的排前面，能系统接口就别模拟输入
- 先看再动：`list_dir` / `read_file` / `snapshot`（看界面）/ `process(action="list")` /
  `clipboard(action="get")` / `registry(action="get")` / `plane` 的
  `query_state`（`compact=true`）——**确认过再写**。
- 优先级：结构化接口 > 模拟键鼠。能用 `run_command`、`read_file`/`write_file`、`clipboard`、
  `app(mode="switch")` 办成的事，就不要去点像素——**这一版的 `click`/`type`/`scroll`/`move` 会真的
  移动老师的鼠标、真的按键**，没有"不打扰老师"的后门。`plane` 的结构化 action > 拼命令字符串。
- 拿不准参数就先查最小的那一份（一个对象、一个窗口、文件头 50 行），别整目录整文件倒进来。

## 4. 能不能一轮里一起发
- **可以并行**：两个都只是"看"、而且互不相关（两个文件、两个窗口、两个只读查询）。
- **必须串行**：写同一个文件、操作同一个窗口、动同一批对象——它们有先后依赖，
  一起发就是互相覆盖（"混乱冲突"多半出在这里）。
- 有依赖的下一步，等结果回来再决定参数；不要提前猜着发。

## 5. 报错怎么处理
- **读原话**：工具报错里经常点名了哪个参数不对、给了正确示例，照着改就行，别换个写法瞎试。
- 被拒绝（权限/确认/环境不支持）就去说明原因或换路子，别反复重试同一个调用。
- 说实话：没成功就说没成功，带上屏幕/报错里的原话；不要用"应该已经好了"糊过去。

## 6. 做完就停
- 一件事做完了不要再"顺手"多做：不额外截屏验收、不额外改别的文件、不额外补充说明。
- 收尾就三件事：**做了什么、东西在哪（绝对路径）、哪些没验/有什么遗留**。
