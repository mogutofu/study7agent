# 读材料：先定位、再按段读、别倒整坨

老师的机器和上下文都不是无限的。下面是省时间也省钱的路子。

## 1. 先定位，再读
- 找文件：`list_dir` 的 **`pattern`** 参数（例如 `*.pptx`、`第*单元*`）先过滤，别把整个目录列出来再用眼睛筛。
- 看内容：**先读头 50–80 行**（`read_file` 的 `start_line` / `max_lines`）判断这是什么、结构怎样，
  再决定要不要往下读。
- 一次读不要超过 200 行。要更多就再读一段，并在心里记下"我已经知道什么、还缺什么"。

## 2. 同一份材料别读两遍
- 第二次读之前先问自己：**我缺的是哪一段？** 有答案就按 `start_line` 直接跳过去。
- 已经读过的内容不要再调一次工具确认；要确认的是"它有没有被改动"（改过才值得重读）。
- **例外**：刚做出来的东西（新写的文件、刚改完的对象、刚导出的稿子）**必须读回来验证** ——
  那不算"读两遍"，《work-loop》里"每步验证"就是这个意思。

## 3. 大文件、图片、压缩包
- 图片先 `inspect_media` 看体积/格式，几十 MB 的图不要直接 `read_file`；
  真要看清就 `view_image`（它会自动降采样）。
- 视频/音频先 `inspect_media` 做编码体检，不要试图"读"它们。
- zip 交给 `read_file`（服务端会解压到工作区并给目录树），别用 run_command 解压再翻。

## 4. 输出要提炼，不要复述
- 工具回了很长的内容时，**只把结论和要用的那两三行放进回答**；不要把整段原文抄给老师。
- 要"现在是什么状态"就用结构化接口：`plane` 的 `query_state`（`compact=true`）、
  `list_objects`、`snapshot`（窗口清单与元素清单，别用 `read_text=true` 拉整篇正文）——
  它们本来就是精简版。
- 需要给老师看清单时，用"名称 + 一行要点"的列表，而不是原始 JSON。

## 5. 什么时候值得花上下文
- 老师明确要看的那份文件、要改的那段正文：**该读全就读全**，别为了省而漏掉关键约束。
- 判断标准：这份内容会不会改变我的下一步？会，就完整读；不会，就读摘要。
